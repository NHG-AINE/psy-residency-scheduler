# Resident request preferences

- Resolve request posting and period against the uploaded catalogue and planning year. Remarks remain recorded without interpretation.
- Match service and, when specified, institution exactly after normalising case and spacing. Unmarked requests prefer core with remaining requirements and otherwise accept one uniquely eligible unfinished elective service. If every match is completed, retain the completed-requirement explanation. Explicit (Core) and (Elective) suffixes restrict the category. Standalone regional annotations such as (East) are ignored for matching; meaningful parentheses remain part of the name. Unclear or competing requests remain pending and do not block a draft.
- Blank periods allow any valid start in the planning year. Explicit periods retain block-aligned starts within the requested window; a block may carry beyond the planning-year boundary. A matching valid placement fulfils the request when it starts, even if LOA pauses it or training remains for next year. Request fulfilment is separate from training completion.
- R5 elective requests use the selected posting's legal three- or six-month block durations. A January-March request cannot be fulfilled by a six-month January-June block. A block may carry beyond June under the usual planning-boundary rule; recognised continuation consumes only its remaining months. R5 uses one six-month elective by default; an evaluable request calling for three months permits a 3+3 route, including free choice of the other block. A bounded three-month window or a mandatory three-month option establishes this exception. Blank or six-month windows alone do not enable it, including multiple different broad requests that may be alternatives. Two compatible three-month elective requests share the six-month total.
- Duplicate rows count once. Maximise each resident's fraction of evaluable requests fulfilled, subject to hard constraints and the shared priority order.
- Draft outcomes describe planned assignments, not completed training credit.
